# Plan: Separar Landing Pública de Admin Dashboard

## Problema Crítico Actual

El middleware redirige TODOS los usuarios no autenticados a `/login` — incluyendo la landing page en `/`. **La landing es inaccesible sin loguearse.**

## Objetivo

1. Landing pública en `/` sin auth (demos + contacto)
2. Dashboard admin en `/dashboard` solo para el fundador
3. API routes protegidas con check admin

---

## Arquitectura de Acceso

```
Rutas públicas (sin auth):  / , /login, /register
Rutas admin (auth + email): /dashboard, /leads, /industries, /analytics, /chat, /webhooks, /api/*
```

**Control de acceso**: Whitelist de emails en variable de entorno `ADMIN_EMAILS`. Solo `juanjovt16@gmail.com` puede entrar al dashboard.

---

## Pasos de Implementación

### Paso 1: Crear `src/lib/admin.ts` (nuevo)

Módulo compartido con la whitelist y función `isAdmin()`.

```ts
const raw = process.env.ADMIN_EMAILS ?? "";
export const ADMIN_EMAILS = raw.split(",").map(e => e.trim().toLowerCase()).filter(Boolean);
export function isAdmin(email: string): boolean {
  return ADMIN_EMAILS.includes(email.toLowerCase());
}
```

### Paso 2: Fix `src/lib/supabase/middleware.ts`

Reemplazar la lógica de rutas:
- Definir `PUBLIC_PATHS = ["/", "/login", "/register"]`
- Rutas públicas → pass through (con refresh de sesión)
- Rutas protegidas sin user → redirect `/login`
- Rutas protegidas con user no-admin → redirect `/?unauthorized=1`
- Rutas protegidas con user admin → pass through

### Paso 3: Actualizar `src/lib/supabase/auth.ts`

Agregar `requireAdmin()` que compone `requireAuth()` + check de `isAdmin()`. Retorna 403 (no 401) para no-admins.

### Paso 4: Actualizar `src/app/(dashboard)/layout.tsx`

Agregar check admin como segunda defensa:
```ts
if (!isAdmin(user.email ?? "")) redirect("/?unauthorized=1");
```

### Paso 5: Actualizar las 16 API routes

Cambio mecánico: `requireAuth()` → `requireAdmin()` en todas las rutas.
